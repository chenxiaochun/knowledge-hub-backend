1. 读者画像与目标

  • 读者：前端背景，Nest 简单 CRUD 会；弱项在鉴权、多存储、MQ、检索流水线。
  • 终态：练习仓能力对齐 origin 主链路（用户/鉴权 → 文档同步 → MQ → 全文/向量/图谱）。
  • 成功标准：只读某课 HTML + origin 对照路径就能动手，不依赖聊天记录。

2. 已拍板的产品决策

4. 单课固定骨架（写新课时照抄）

  1. 一句话目标 + 自测验收（curl / 预期现象；本课要 docker compose up 哪些服务）
  2. 概念（前端类比表 + 为何这样拆 + 可选 flow 图）
  3. 本课文件清单（路径 + 新建/核对）
  4. 逐步实现（命令 → 完整文件内容写在该步骤下；可复制按钮）
  5. 与 origin 差异（练习版故意简化的表）
  6. 常见报错

交互约定：左侧锚点目录、代码块一键复制、返回顶部；样式可复用课 1 / origin learn-guide.html。

5. 写代码进讲义时的原则

  • 可运行优先：练习版允许砍字段/砍接口，但按步骤做完应能 curl 过关。
  • 对齐命名：表名、模块名尽量跟 origin（如 kh_user），方便对照。
  • 差异显式：凡是比 origin 少的，必须在「差异」一节写清，避免读者以为仓库就那么简单。
  • 不讲算法课：Embedding / KG 只到「怎么接、数据怎么流」。
  • 环境变量：每课写清 .env 增量；提醒勿提交密钥。
  • 路由陷阱等：像 GET page 必须在 :id 前这类坑，写进正文或报错表。

7. 后续续写检查清单

  1. 打开本页 + design spec，确认该课依赖与简化边界。
  2. 对照 origin 对应目录，列出「练习版必做 / 可砍」。
  3. 按第 4 节骨架写 HTML；正文给完整代码。
  4. 自测：按讲义 curl（或等价步骤）在头脑里走通一遍。
  5. 更新 index.html：该课链接从「待写」改为「可学」。
  6. 提交练习仓；勿提交 .env / 密钥。
