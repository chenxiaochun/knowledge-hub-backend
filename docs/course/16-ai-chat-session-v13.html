目标与验收

在课 14「混合检索 + LLM 作答 + sources」之上，按 origin v13 补齐 多轮对话历史：会话表 + 消息表、本人可见的会话 CRUD、 每次问答落库一对 user/assistant 消息。

本课只写讲义：在练习仓自己改 src/ai/；对照答案看 knowledge-hub-backend-origin 分支 v13。 不替你改业务代码。
验收清单
  1. 不带 sessionId 调 POST /ai/chat：返回新 sessionId；库表 kh_ai_session / kh_ai_message 各有记录
  2. 带同一 sessionId 再问一轮：消息按时间递增；会话 updatedAt 更新；标题若仍是「新对话」会被首问覆盖
  3. GET /ai/sessions 只看到当前用户的会话；别人的 id 返回 404
  4. GET /ai/sessions/:id/messages 能回放完整对话；assistant 行可带 sources JSON
  5. 重命名、删除会话（删会话时级联删消息）成功
前置： 课 14 已通（至少能 POST /ai/chat 拿到 answer + sources）； JWT 登录可用（要有 userId）；Postgres 可写表。 权限可用课 09 的 @RequirePermission(search)，或临时 @Roles(ADMIN)。

概念与数据模型

用户提问 →（可选）带 sessionId → 检索 + LLM（课 14 已有） → ChatSessionService.appendTurn · 无 sessionId → 新建会话（标题=首问截断） · 有 sessionId → 校验归属 · 写 user 消息 + assistant 消息（sources JSONB） · 刷新 session.updatedAt → 响应 { sessionId, answer, sources } 侧栏：GET /ai/sessions（按 updatedAt 倒序） 点开：GET /ai/sessions/:id/messages（按 createdAt 正序）
表职责关键字段
kh_ai_session 一次「对话线程」 id、user_id、title、updated_at
kh_ai_message 一轮里的一条消息 session_id、role（user/assistant）、content、sources（仅助手）

归属：所有读改删都带 where: { id, userId }，避免越权看别人历史。 不在本课做：把历史消息再喂回 LLM 当多轮上下文（那是后续增强）；本课只做持久化与回放。

  4. ChatSessionService（核心）

    src/ai/chat-session.service.ts

    import { Injectable, NotFoundException } from '@nestjs/common';
import { InjectEntityManager } from '@nestjs/typeorm';
import { EntityManager } from 'typeorm';
import { nextSnowflakeId } from '../common/snowflake-id';
import { AiSessionEntity } from './entities/ai-session.entity';
import { AiMessageEntity } from './entities/ai-message.entity';
import type { ChatSource } from './chat.types';
import {
  CreateSessionDto,
  QuerySessionDto,
  UpdateSessionDto,
} from './dto/session.dto';

const DEFAULT_TITLE = '新对话';

@Injectable()
export class ChatSessionService {
  constructor(
    @InjectEntityManager()
    private readonly em: EntityManager,
  ) {}

  async pageMine(userId: string, query: QuerySessionDto) {
    const page = query.page ?? 1;
    const pageSize = query.pageSize ?? 20;
    const [items, total] = await this.em.findAndCount(AiSessionEntity, {
      where: { userId },
      order: { updatedAt: 'DESC' },
      skip: (page - 1) * pageSize,
      take: pageSize,
    });
    return { items, total, page, pageSize };
  }

  async create(userId: string, dto: CreateSessionDto) {
    const title = dto.title?.trim() || DEFAULT_TITLE;
    const session = this.em.create(AiSessionEntity, {
      id: nextSnowflakeId(),
      userId,
      title: title.slice(0, 80),
    });
    return this.em.save(session);
  }

  async rename(userId: string, id: string, dto: UpdateSessionDto) {
    const session = await this.getOwned(userId, id);
    session.title = dto.title.trim().slice(0, 80);
    return this.em.save(session);
  }

  async remove(userId: string, id: string) {
    await this.getOwned(userId, id);
    // 即使库有 ON DELETE CASCADE，也显式删消息更清晰
    await this.em.delete(AiMessageEntity, { sessionId: id });
    await this.em.delete(AiSessionEntity, { id });
    return { message: '已删除' };
  }

  async listMessages(userId: string, sessionId: string) {
    await this.getOwned(userId, sessionId);
    return this.em.find(AiMessageEntity, {
      where: { sessionId },
      order: { createdAt: 'ASC', id: 'ASC' },
    });
  }

  /**
   * 问答落库：无 sessionId 则新建；标题仍为默认名时用首问覆盖。
   */
  async appendTurn(
    userId: string,
    sessionId: string | undefined,
    question: string,
    answer: string,
    sources: ChatSource[],
  ) {
    const session = sessionId
      ? await this.getOwned(userId, sessionId)
      : await this.create(userId, { title: titleFromQuestion(question) });

    if (session.title === DEFAULT_TITLE) {
      session.title = titleFromQuestion(question);
    }
    session.updatedAt = new Date();
    await this.em.save(session);

    const userMsg = this.em.create(AiMessageEntity, {
      id: nextSnowflakeId(),
      sessionId: session.id,
      role: 'user',
      content: question,
    });
    const assistantMsg = this.em.create(AiMessageEntity, {
      id: nextSnowflakeId(),
      sessionId: session.id,
      role: 'assistant',
      content: answer,
      sources: sources.length ? sources : null,
    });
    await this.em.save([userMsg, assistantMsg]);
    return session;
  }

  private async getOwned(userId: string, id: string) {
    const session = await this.em.findOne(AiSessionEntity, {
      where: { id, userId },
    });
    if (!session) {
      throw new NotFoundException('会话不存在');
    }
    return session;
  }
}

function titleFromQuestion(question: string) {
  const text = question.replace(/\s+/g, ' ').trim();
  if (!text) return DEFAULT_TITLE;
  return text.length > 30 ? `${text.slice(0, 30)}…` : text;
}

1. 改 AiChatService.chat 签名

在已有检索 + LLM 逻辑之后调用 appendTurn； 「无召回」「空问题」也建议落库，方便侧栏回放（与 v13 一致）。 

constructor(
  config: ConfigService,
  private readonly retrieval: HybridRetrievalService,
  private readonly sessions: ChatSessionService, // 新增
) { … }

async chat(
  question: string,
  topK = 5,
  user?: AuthUser,
  sessionId?: string,
) {
  const trimmed = question.trim();
  if (!trimmed) {
    return {
      sessionId: sessionId ?? null,
      answer: '请输入问题。',
      sources: [] as ChatSource[],
    };
  }

  const hits = await this.retrieval.retrieve(trimmed, topK);
  if (!hits.length) {
    const empty = {
      answer: '知识库里没有相关内容。',
      sources: [] as ChatSource[],
    };
    const session = user
      ? await this.sessions.appendTurn(
          user.userId,
          sessionId,
          trimmed,
          empty.answer,
          empty.sources,
        )
      : null;
    return { sessionId: session?.id ?? sessionId ?? null, ...empty };
  }

  // … 原有 LLM invoke + toCitedSources …

  const session = user
    ? await this.sessions.appendTurn(
        user.userId,
        sessionId,
        trimmed,
        answer,
        sources,
      )
    : null;

  return { sessionId: session?.id ?? sessionId ?? null, answer, sources };
}

2. Controller：CurrentUser + 会话路由

路径前缀：origin 用 @Controller()，路由是 POST /ai/chat、GET /ai/sessions。 若你练习仓是 @Controller('ai')，请把方法路径改成 chat / sessions（避免变成 /ai/ai/chat）， 或改成与 origin 一样的空前缀。下面按 origin 路径写。 
@Controller()
export class AiController {
  constructor(
    private readonly aiChat: AiChatService,
    private readonly retrieval: HybridRetrievalService,
    private readonly sessions: ChatSessionService,
  ) {}

  @Post('rag/search')
  @RequirePermission(PermissionCode.search)
  search(@Body() dto: RagSearchDto) {
    return this.retrieval.retrieve(dto.query.trim(), dto.topK ?? 5);
  }

  @Post('ai/chat')
  @RequirePermission(PermissionCode.search)
  chat(@Body() dto: ChatDto, @CurrentUser() user: AuthUser) {
    return this.aiChat.chat(
      dto.content,
      dto.topK ?? 5,
      user,
      dto.sessionId,
    );
  }

  @Get('ai/sessions')
  @RequirePermission(PermissionCode.search)
  listSessions(
    @Query() query: QuerySessionDto,
    @CurrentUser() user: AuthUser,
  ) {
    return this.sessions.pageMine(user.userId, query);
  }

  @Post('ai/sessions')
  @RequirePermission(PermissionCode.search)
  createSession(
    @Body() dto: CreateSessionDto,
    @CurrentUser() user: AuthUser,
  ) {
    return this.sessions.create(user.userId, dto);
  }

  // 静态段 messages 在 :id 之后没关系；注意不要用会吞掉 sessions 的路由
  @Get('ai/sessions/:id/messages')
  @RequirePermission(PermissionCode.search)
  listMessages(@Param('id') id: string, @CurrentUser() user: AuthUser) {
    return this.sessions.listMessages(user.userId, id);
  }

  @Patch('ai/sessions/:id')
  @RequirePermission(PermissionCode.search)
  renameSession(
    @Param('id') id: string,
    @Body() dto: UpdateSessionDto,
    @CurrentUser() user: AuthUser,
  ) {
    return this.sessions.rename(user.userId, id, dto);
  }

  @Delete('ai/sessions/:id')
  @RequirePermission(PermissionCode.search)
  removeSession(@Param('id') id: string, @CurrentUser() user: AuthUser) {
    return this.sessions.remove(user.userId, id);
  }
}

设计决策

为什么拆 Session / Message 两张表？

侧栏只要会话列表（轻）；点开再拉消息（重）。一条问答写成两条消息，方便前端按聊天气泡渲染， 也方便以后只把最近 N 条 user/assistant 拼进 LLM 上下文。

为什么标题用首问截断？

空会话默认「新对话」；第一次真正提问后用问题前 30 字当标题，侧栏可扫读。 用户仍可 PATCH 重命名。

为什么 sources 只挂在 assistant？

溯源是「回答依据了哪些块」；用户问题本身没有 sources。JSONB 存摘录即可，不必再查 ES。

常见报错

现象排查
401 / 无 userIdchat 是否注入 @CurrentUser()；JWT 是否带用户
会话 404是否用了别人的 sessionId；或删过后还在用
有 answer 无落库是否忘了 appendTurn；user 是否 undefined
表不存在跑 init.sql；AppModule entities 是否注册
/ai/ai/chat 404Controller 前缀重复；对照「路径前缀」警告
标题一直「新对话」create 时已用首问作 title，不会进 DEFAULT 分支；或比较字符串不全等
删除会话后消息还在是否只删了 session；应先删 message 或依赖 CASCADE
sources 列类型错Postgres 用 jsonb；TypeORM type: 'jsonb'
