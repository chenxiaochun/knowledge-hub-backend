目标与验收

前置：第 4 课 MQ 发布已通；建议已完成 课 09（也可用 @Roles(ADMIN) 临时过关）。

本课：用 kh_document_review 记录审核流水，不再只改 Document.status。

验收
  1. Draft → submit-review：文档 PendingReview，表中一条 review_result IS NULL
  2. approve：记录结案 + 文档 Published + MQ INDEX 日志
  3. 另开文档 reject：回 Draft，记录有 comment
  4. DOCUMENT_REQUIRE_APPROVAL=false 时可直接 publish（兼容课 4）

概念

Draft ──publish/submit──► PendingReview ──approve──► Published PendingReview ──reject──► Draft Published ──archive──────► Archived（清索引） Published ──save-draft───► Draft（清索引） Published ──改稿+submit──► PendingReview（先清旧索引） 开关 DOCUMENT_REQUIRE_APPROVAL（默认 true；false 时 publish 直发+MQ）

课 4 极简版把「审核」缩成状态翻转；本课补可追溯流水。完整状态机对齐 origin v6，见文末 教你怎么对齐 v6。

  2. DocumentReviewService（完整）

    src/document/document-review.service.ts

    import {
  BadRequestException,
  Injectable,
  Logger,
  NotFoundException,
} from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { InjectRepository } from '@nestjs/typeorm';
import { IsNull, Repository } from 'typeorm';
import { nextSnowflakeId } from '../common/snowflake-id';
import { DocumentPipelinePublisher } from '../mq/document-pipeline.publisher';
import { DocumentStatus } from './document-status'; // 或你课 3/4 的枚举文件
import { DocumentEntity } from './entities/document.entity';
import {
  DocumentReviewEntity,
  ReviewResult,
} from './entities/document-review.entity';
import type { AuthUser } from '../auth/auth-user.interface';

@Injectable()
export class DocumentReviewService {
  private readonly logger = new Logger(DocumentReviewService.name);

  constructor(
    @InjectRepository(DocumentReviewEntity)
    private readonly reviewRepo: Repository<DocumentReviewEntity>,
    @InjectRepository(DocumentEntity)
    private readonly docRepo: Repository<DocumentEntity>,
    private readonly pipelinePublisher: DocumentPipelinePublisher,
    private readonly config: ConfigService,
  ) {}

  isRequireApproval(): boolean {
    return (
      this.config.get<string>('DOCUMENT_REQUIRE_APPROVAL', 'true') !== 'false'
    );
  }

  private async findDoc(id: string) {
    const doc = await this.docRepo.findOne({ where: { id, deleted: false } });
    if (!doc) throw new NotFoundException('文档不存在');
    return doc;
  }

  async submitForReview(documentId: string, actor?: AuthUser) {
    const doc = await this.findDoc(documentId);
    if (
      doc.status !== DocumentStatus.Draft &&
      doc.status !== DocumentStatus.Published
    ) {
      throw new BadRequestException('只有草稿或已发布可提交审核');
    }

    const pending = await this.reviewRepo.findOne({
      where: { documentId, reviewResult: IsNull() },
    });
    if (pending) throw new BadRequestException('该文档已有待审核任务');

    const beforeStatus = doc.status;
    const review = this.reviewRepo.create({
      id: nextSnowflakeId(),
      documentId,
      beforeStatus,
    });
    await this.reviewRepo.save(review);

    doc.status = DocumentStatus.PendingReview;
    await this.docRepo.save(doc);
    this.logger.log(`已提交审核 reviewId=${review.id} doc=${documentId}`);
    return { document: doc, review };
  }

  async approveReview(
    reviewId: string,
    actor: AuthUser,
    comment?: string,
  ) {
    const review = await this.reviewRepo.findOne({ where: { id: reviewId } });
    if (!review || review.reviewResult != null) {
      throw new BadRequestException('待审任务不存在或已结案');
    }

    review.reviewResult = ReviewResult.Approved;
    review.reviewerId = actor.userId;
    review.reviewerName = actor.username;
    review.reviewComment = comment ?? null;
    review.reviewedAt = new Date();
    await this.reviewRepo.save(review);

    const doc = await this.findDoc(review.documentId);
    doc.status = DocumentStatus.Published;
    doc.publishTime = new Date();
    const saved = await this.docRepo.save(doc);

    // 与课 4 publish 一致：投递失败不回滚
    await this.pipelinePublisher.afterPublish(saved.id);
    this.logger.log(`审核通过 reviewId=${reviewId}`);
    return saved;
  }

  async rejectReview(reviewId: string, actor: AuthUser, comment: string) {
    const review = await this.reviewRepo.findOne({ where: { id: reviewId } });
    if (!review || review.reviewResult != null) {
      throw new BadRequestException('待审任务不存在或已结案');
    }
    if (!comment?.trim()) {
      throw new BadRequestException('驳回必须填写原因');
    }

    review.reviewResult = ReviewResult.Rejected;
    review.reviewerId = actor.userId;
    review.reviewerName = actor.username;
    review.reviewComment = comment;
    review.reviewedAt = new Date();
    await this.reviewRepo.save(review);

    const doc = await this.findDoc(review.documentId);
    doc.status = DocumentStatus.Draft;
    await this.docRepo.save(doc);
    this.logger.log(`审核驳回 reviewId=${reviewId}`);
    return doc;
  }

  async listPending() {
    return this.reviewRepo.find({
      where: { reviewResult: IsNull() },
      order: { createdAt: 'DESC' },
    });
  }

  /** 供 DocumentService.publish 调用：开启审核时禁止直接发布 */
  assertCanDirectPublish() {
    if (this.isRequireApproval()) {
      throw new BadRequestException(
        '已开启审核，请走 submit-review → approve',
      );
    }
  }
}

设计决策

为什么 approve 按 reviewId 而不是 documentId？

同一文档可有多条历史；结案必须对准「那一条待审」。列表接口返回 reviewId 给审核人。

为什么「待审」用 review_result IS NULL，不用 reviewer_id IS NULL？

待审语义是「还没出结果」。审核人字段结案时才填；用 reviewer 判断会和「未来预分配审核人」等扩展冲突。 表索引也按 review_result IS NULL 建（见 origin init.sql）。

对照 origin（分支 v6）

  1. src/document/document-status.ts（流转辅助函数）
  2. src/document/document-review.service.ts
  3. src/document/document.service.ts 的 publish / archive / saveAsDraft
  4. curl-document-status.md 整条状态机 curl
  5. 环境变量 DOCUMENT_REQUIRE_APPROVAL

与 origin v6 差异

origin v6本课步骤 / 常见练习仓
publish 需审时进 PendingReview，不投索引若仍「直发 + afterPublish」，须按 对齐练习 改
Published 再提审先 afterUnpublish常漏清索引 → 审核中仍能搜到旧文
待审判定 reviewResult IS NULL误用 reviewerId IS NULL 时要对齐
列名 reviewer_id / reviewed_at勿写成 review_id / review_at
archive / save-draft + 待审禁改本课可后补；对齐练习有教法
分页 tasks / history / pending-count步骤可先只做 pending 列表
EntityManagerRepository 注入亦可

教你怎么对齐 origin v6

原则：讲义只教你怎么写，不替你改练习仓 src/。 打开自己的 document.service.ts / document-review.service.ts / controller / entity， 按练习顺序改；对照答案看 origin 分支 v6。

练习 0 · 先修路由顺序与列名

为什么：静态路由被 :id 吃掉时，待办列表永远 404/详情错乱，后面全测不准。 列名错则和 init.sql / origin 对不上。

  1. 把 reviews/* 全部挪到 @Get(':id') 之前（见上文 Controller 示例）。
  2. Entity 对齐： name: 'reviewer_id'、name: 'reviewed_at'； 不要用 review_id / review_at。
  3. 若库表已错建：开发环境可删表或改列后重启（有数据先备份）。

自测：GET …/reviews/pending 返回数组，而不是「文档不存在」。

练习 2 · DOCUMENT_REQUIRE_APPROVAL + 改写 publish

为什么：v6 的「发布」在需审模式下等于「提交审核」；只有免审或 approve 之后才进索引。 若 publish 仍直接 Published + afterPublish，审核台形同虚设。

在哪改：ReviewService 加开关；DocumentService.publish 分支；Approve 继续投 MQ。

// document-review.service.ts
constructor(
  …,
  private readonly config: ConfigService,
) {}

isRequireApproval(): boolean {
  return (
    this.config.get<string>('DOCUMENT_REQUIRE_APPROVAL', 'true') !== 'false'
  );
}
// document.service.ts — 注入 DocumentReviewService
async publish(id: string, actor: AuthUser) {
  const doc = await this.docRepo.findOne({ where: { id, deleted: false } });
  if (!doc) throw new NotFoundException('文档不存在');

  if (doc.status === DocumentStatus.PendingReview) {
    throw new BadRequestException('文档审核中，请等待审核结果');
  }

  // 需审核：进入待审，不投索引
  if (this.reviewService.isRequireApproval()) {
    if (
      doc.status === DocumentStatus.Draft ||
      doc.status === DocumentStatus.Published
    ) {
      return this.reviewService.submitForReview(id, actor);
    }
    throw new BadRequestException('当前状态不允许发布');
  }

  // 免审：直接发布（兼容课 4）
  return this.directPublish(id);
}

/** 免审直发；也可给 approve 复用「写状态」以外的逻辑 */
private async directPublish(id: string) {
  const doc = await this.docRepo.findOne({ where: { id, deleted: false } });
  if (!doc) throw new NotFoundException('文档不存在');

  doc.status = DocumentStatus.Published;
  doc.publishTime = new Date();
  const saved = await this.docRepo.save(doc);
  try {
    await this.pipelinePublisher.afterPublish(saved.id);
  } catch (e) {
    this.logger.warn(`发布后索引投递失败：${e}`);
  }
  return saved;
}

练习 3 · 已发布再提审：先清索引

为什么：审核期间文档不应可检索。v6 在 submitForReview 里若 beforeStatus === Published，先 afterUnpublish。 

async submitForReview(documentId: string, actor: AuthUser) {
  const doc = await this.findDoc(documentId); // 记得 where: { id, deleted: false }
  if (
    doc.status !== DocumentStatus.Draft &&
    doc.status !== DocumentStatus.Published
  ) {
    throw new BadRequestException('只有草稿或已发布文档可以提交审核');
  }

  const pending = await this.documentReviewRepository.findOne({
    where: { documentId, reviewResult: IsNull() },
  });
  if (pending) throw new BadRequestException('该文档已有待审核任务');

  const beforeStatus = doc.status;
  const review = this.documentReviewRepository.create({
    id: nextSnowflakeId(),
    documentId,
    beforeStatus,
  });
  await this.documentReviewRepository.save(review);

  doc.status = DocumentStatus.PendingReview;
  await this.documentRepository.save(doc);

  // 关键点：来自已发布 → 先下架索引
  if (beforeStatus === DocumentStatus.Published) {
    try {
      await this.documentPipelinePublisher.afterUnpublish(documentId);
    } catch (e) {
      this.logger.warn(`提审后清索引失败：documentId=${documentId}, ${e}`);
    }
  }

  return { document: doc, review };
}

自测：已发布文档能搜到 → 再 publish/submit → 立刻搜不到 → approve → 又能搜到。

export function canPublishFrom(status: DocumentStatus): boolean {

    status === DocumentStatus.Published ||
    status === DocumentStatus.Archived ||

  return (

  return status === DocumentStatus.Published;

练习 5 · archive / save-draft

为什么：已发布下架有两种产品语义——归档保留「已归档」态，或退回草稿再改。都必须清索引。

async archive(id: string) {
  const doc = await this.docRepo.findOne({ where: { id, deleted: false } });
  if (!doc) throw new NotFoundException('文档不存在');
  if (!canArchive(doc.status)) {
    throw new BadRequestException('只有已发布文档可以归档');
  }
  doc.status = DocumentStatus.Archived;
  const saved = await this.docRepo.save(doc);
  try {
    await this.pipelinePublisher.afterUnpublish(id);
  } catch (e) {
    this.logger.warn(`归档清索引失败：${e}`);
  }
  return saved;
}

async saveAsDraft(id: string) {
  const doc = await this.docRepo.findOne({ where: { id, deleted: false } });
  if (!doc) throw new NotFoundException('文档不存在');
  if (doc.status !== DocumentStatus.Published) {
    throw new BadRequestException('只有已发布文档可以保存为草稿');
  }
  doc.status = DocumentStatus.Draft;
  const saved = await this.docRepo.save(doc);
  try {
    await this.pipelinePublisher.afterUnpublish(id);
  } catch (e) {
    this.logger.warn(`下架清索引失败：${e}`);
  }
  return saved;
}

  1. 练习 0 → 1（路由、列名、待审条件）
  2. 练习 2 → 3（publish 走审核 + 提审清索引）——主流程对齐 v6
  3. 练习 4 → 5 → 6（状态机完整）
  4. 有余力再做练习 7

总验收 curl（对齐 v6）

BASE=http://localhost:3000
TOKEN=…   # 登录后的 Bearer
DOC_ID=…  # 上传得到的草稿 id

# 1) 需审发布 → status=3，不进索引
curl -s -X PUT "$BASE/document/${DOC_ID}/publish" \
  -H "Authorization: Bearer $TOKEN" | jq '{id, status}'

# 2) 待办（路径以你 Controller 为准）
curl -s "$BASE/document/reviews/pending" \
  -H "Authorization: Bearer $TOKEN" | jq

# 3) 通过 → status=1 + MQ
TASK_ID=…  # pending 列表里的 id
curl -s -X PUT "$BASE/document/reviews/${TASK_ID}/approve" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"comment":"准予发布"}' | jq '{id, status, publishTime}'

# 4) 已发布再提审 → 应搜不到旧文，再 approve 恢复
# 5) reject 须带 comment；PendingReview 时改标题应 400
# 6) DOCUMENT_REQUIRE_APPROVAL=false 重启后，publish 可直发
