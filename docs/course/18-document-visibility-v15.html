目标与验收

把「谁能看见哪篇文档」贯穿到列表 / 详情 / 全文搜索 / RAG / 图谱。 规则与 origin v15 一致：普通用户只能看到 自己写的 ∪ 已发布且公开 ∪ 已发布且所在团队； ADMIN / REVIEWER 不限制。

本课只写讲义：在练习仓手敲；对照 origin v15。 不替你改业务代码。
验收清单
  1. JWT / AuthUser 带 teamIds（成员 ∪ 负责人）
  2. 用户 A 看不到用户 B 的草稿、非公开非本团队已发布文档（列表不出现，详情 403）
  3. POST /search、POST /ai/rag/search、GET /graph/* 同样按可见性过滤
  4. 已发布文档只改 isPublic / teamId 时，ES / 向量 / Neo4j 立刻刷可见性字段（不必重算向量）
  5. 管理员搜得到所有已索引文档；普通用户搜不到无权文档
前置：课 05（ES 全文）+ 课 11（团队）建议已通；课 14（混合检索）/ 课 15（图谱）若已做，本课在其上打洞。 需要 Postgres + ES（+ 可选 Neo4j / Embedding）。

概念与规则

可见性规则（一张表）

角色 / 情况能看见
ADMIN / REVIEWER全部（列表、搜索、RAG、图谱都不加 filter）
作者本人自己的任意状态（含草稿 / 待审）
普通用户 + 已发布 + isPublic可见
普通用户 + 已发布 + teamId ∈ teamIds可见
其它不可见

为什么要「三套索引一起管」

Postgres 元数据（列表 / 详情） │ canReadDocument / SQL WHERE │ ES kh_document（全文搜）── filter: isPublic | authorId | teamId ES kh_chunk（RAG）────── filter / knn.filter 同上（snake_case） Neo4j KnowledgeDocument ─ Cypher WHERE 同上 │ 改 isPublic / teamId（仍 Published） └─► PipelineOrchestrator.updateVisibility ├─ SearchIndex.updateVisibility ├─ VectorIndex.updateVisibility └─ GraphBuild.updateVisibility
关键设计：可见性放 ES filter，相关性放 must， 权限条件不参与打分。索引侧假定「未发布不会进索引」， ES filter 不再判断 status；Postgres 列表仍要判断 Published。

async listAccessibleTeamIds(userId: string): Promise<string[]> {
  const [memberRows, led] = await Promise.all([
    this.memberRepo
      .createQueryBuilder('m')
      .select('m.team_id', 'teamId')
      .where('m.user_id = :userId', { userId })
      .getRawMany<{ teamId: string | number }>(),
    this.teamRepo.find({
      where: { leaderId: userId, deleted: false },
      select: ['id'],
    }),
  ]);
  const ids = [
    ...new Set([
      ...memberRows.map((row) => String(row.teamId)),
      ...led.map((row) => String(row.id)),
    ]),
  ];
  if (!ids.length) return [];
  const teams = await this.teamRepo.find({
    where: { id: In(ids), deleted: false },
    select: ['id', 'teamName'],
  });
  return teams.map((row) => String(row.id));
}

async listMine(userId: string): Promise<TeamEntity[]> {
  const ids = await this.listAccessibleTeamIds(userId);
  if (!ids.length) return [];
  return this.teamRepo.find({
    where: { id: In(ids), deleted: false },
    order: { sort: 'ASC', createdAt: 'ASC' },
  });
}

2. document-access（规则中枢）

src/document/document-access.ts（新建，完整可粘贴）

所有「能不能看 / ES filter / Cypher WHERE」集中在此，避免三套存储各写一套规则。

import { RoleCode } from '../common/constants/roles';
import type { AuthUser } from '../auth/auth-user.interface';
import { DocumentStatus } from './document-status';
import type { DocumentEntity } from './entities/document.entity';

/** 当前用户可读哪些文档：公开 ∪ 所在团队 ∪ 自己写的；管理员/审核员不限制 */
export type DocumentAccessScope = {
  unrestricted: boolean;
  userId: string;
  teamIds: string[];
};

export function accessFromUser(user: AuthUser): DocumentAccessScope {
  const roles = user.roles ?? [];
  return {
    unrestricted:
      roles.includes(RoleCode.ADMIN) || roles.includes(RoleCode.REVIEWER),
    userId: user.userId,
    teamIds: user.teamIds ?? [],
  };
}

export function canReadDocument(
  doc: Pick<DocumentEntity, 'authorId' | 'teamId' | 'isPublic' | 'status'>,
  scope: DocumentAccessScope,
): boolean {
  if (scope.unrestricted) return true;
  if (doc.authorId && doc.authorId === scope.userId) return true;
  if (doc.status !== DocumentStatus.Published) return false;
  if (doc.isPublic) return true;
  return Boolean(doc.teamId && scope.teamIds.includes(doc.teamId));
}

export function canWriteDocument(
  doc: Pick<DocumentEntity, 'authorId'>,
  user: AuthUser,
): boolean {
  if (user.roles?.includes(RoleCode.ADMIN)) return true;
  return Boolean(doc.authorId && doc.authorId === user.userId);
}

export const ES_CHUNK_VISIBILITY_FIELDS = {
  isPublic: 'is_public',
  authorId: 'author_id',
  teamId: 'team_id',
};

export const ES_DOC_VISIBILITY_FIELDS = {
  isPublic: 'isPublic',
  authorId: 'authorId',
  teamId: 'teamId',
};

/**
 * Elasticsearch 可见性 filter（只筛不打分）。
 * fields 区分 kh_document（camelCase）与 kh_chunk（snake_case）。
 * 管理员/审核员返回 null，调用方不加过滤。
 */
export function esVisibilityFilter(
  scope: DocumentAccessScope,
  fields: { isPublic: string; authorId: string; teamId: string },
): Record<string, unknown> | null {
  if (scope.unrestricted) return null;
  // 公开 ∪ 自己写的；有团队再 OR 所在团队。不判断 status，假定未发布未进索引。
  const should: Record<string, unknown>[] = [
    { term: { [fields.isPublic]: true } },
    { term: { [fields.authorId]: scope.userId } },
  ];
  if (scope.teamIds.length) {
    should.push({ terms: { [fields.teamId]: scope.teamIds } });
  }
  // filter 上下文中 should = 或；至少命中一条才可见
  return { bool: { should, minimum_should_match: 1 } };
}

/** 相关性查询放 must，可见性放 filter，避免权限条件影响打分 */
export function wrapEsQuery(
  query: Record<string, unknown>,
  filter: Record<string, unknown> | null,
): Record<string, unknown> {
  if (!filter) return query;
  return {
    bool: {
      must: [query],
      filter: [filter],
    },
  };
}

export function neo4jAccessParams(scope?: DocumentAccessScope) {
  return {
    unrestricted: !scope || scope.unrestricted,
    accessUserId: scope?.userId ?? '',
    accessTeamIds: scope?.teamIds ?? [],
  };
}

/** Cypher：文档节点是否对当前用户可见 */
export function neo4jDocumentAccessWhere(alias = 'd'): string {
  return (
    `($unrestricted OR ${alias}.authorId = $accessUserId ` +
    `OR ${alias}.isPublic = true OR ${alias}.teamId IN $accessTeamIds)`
  );
}

3.1 列表 findAll

src/document/document.service.ts · controller 传入 @CurrentUser() user

async findAll(query: QueryDocumentDto, user: AuthUser) {
  const page = query.page ?? 1;
  const pageSize = query.pageSize ?? 20;
  const scope = accessFromUser(user);

  const qb = this.em
    .createQueryBuilder(DocumentEntity, 'doc')
    .where('doc.deleted = :deleted', { deleted: false });

  if (!scope.unrestricted) {
    if (scope.teamIds.length) {
      qb.andWhere(
        `(doc.author_id = :me OR (doc.status = :published AND (doc.is_public = true OR doc.team_id IN (:...teamIds))))`,
        {
          me: scope.userId,
          published: DocumentStatus.Published,
          teamIds: scope.teamIds,
        },
      );
    } else {
      qb.andWhere(
        `(doc.author_id = :me OR (doc.status = :published AND doc.is_public = true))`,
        { me: scope.userId, published: DocumentStatus.Published },
      );
    }
  }
  // …原有 title / category / status 筛选与分页不变
}

6. 改公开 / 团队：立刻刷三套索引

已发布文档只改 isPublic / teamId 时，若等再次审核发布才重建索引， 搜索会继续按旧可见性放行——本课最容易漏的坑。

6.1 DocumentService.update

const oldIsPublic = doc.isPublic;
const oldTeamId = doc.teamId ?? null;
// …保存
const visibilityChanged =
  saved.isPublic !== oldIsPublic || (saved.teamId ?? null) !== oldTeamId;

await this.syncPipelineAfterUpdate(
  saved, oldStatus, saved.status, contentChanged, visibilityChanged,
);

private async syncPipelineAfterUpdate(
  doc, oldStatus, newStatus, contentChanged, visibilityChanged,
) {
  const wasPublished = oldStatus === DocumentStatus.Published;
  const isPublished = newStatus === DocumentStatus.Published;

  if (wasPublished && !isPublished) {
    await this.safeUnpublish(doc.id);
    return;
  }
  if (isPublished && contentChanged && !this.reviewService.isRequireApproval()) {
    await this.safePublish(doc);
    return;
  }
  if (isPublished && visibilityChanged) {
    try {
      await this.pipeline.updateVisibility(doc);
    } catch (error) {
      this.logger.warn(`可见性同步失败：${error}`);
    }
  }
}

DocumentModule imports: [PipelineModule]，注入 PipelineOrchestrator。

async updateVisibility(doc: DocumentEntity) {
  const vis = {
    isPublic: doc.isPublic ?? false,
    teamId: doc.teamId ?? null,
    authorId: doc.authorId ?? null,

  await Promise.all([
    this.searchIndexService.updateVisibility(doc.id, vis),
    this.vectorIndexService.updateVisibility(doc.id, vis),

async updateVisibility(documentId: string, vis: {
  isPublic: boolean; teamId: string | null; authorId: string | null;
}) {
  if (!this.es) return;
  await this.es.updateByQuery({
    index: CHUNK_INDEX,
    refresh: true,
    query: { term: { document_id: documentId } },
    script: {
      source:
        'ctx._source.is_public = params.is_public; ' +
        'ctx._source.team_id = params.team_id; ' +
        'ctx._source.author_id = params.author_id;',
      params: {
        is_public: vis.isPublic,
        team_id: vis.teamId,
        author_id: vis.authorId,
      },
    },
  });
}

8. 验收 curl

准备：用户 A、用户 B（不同团队）；文档 D1（A 写、Published、isPublic=false、teamId=A 的团队）；文档 D2（A 写、Draft）。

# 变量
BASE=http://localhost:3000
TOKEN_A=...   # 用户 A
TOKEN_B=...   # 用户 B（不在 D1 团队）
TOKEN_ADMIN=...

# 1) 列表：B 看不到 D1、D2
curl -s -H "Authorization: Bearer $TOKEN_B" "$BASE/documents?page=1" | jq .

# 2) 详情：B 访问 D1 → 403
curl -s -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer $TOKEN_B" "$BASE/documents/$D1_ID"

# 3) 全文搜：B 关键词命中 D1 正文也不应返回
curl -s -X POST "$BASE/search" \
  -H "Authorization: Bearer $TOKEN_B" -H 'Content-Type: application/json' \
  -d '{"keyword":"只有D1才有的词","page":1,"pageSize":10}' | jq .

# 4) RAG
curl -s -X POST "$BASE/ai/rag/search" \
  -H "Authorization: Bearer $TOKEN_B" -H 'Content-Type: application/json' \
  -d '{"query":"只有D1才有的词","topK":5}' | jq .

# 5) 把 D1 改为 isPublic=true 后，B 应能搜到（不必重跑 Embedding）
curl -s -X PUT "$BASE/documents/$D1_ID" \
  -H "Authorization: Bearer $TOKEN_A" -H 'Content-Type: application/json' \
  -d '{"isPublic":true}' | jq .
# 再执行步骤 3，B 应命中

# 6) Admin 始终能搜到
curl -s -X POST "$BASE/search" \
  -H "Authorization: Bearer $TOKEN_ADMIN" -H 'Content-Type: application/json' \
  -d '{"keyword":"只有D1才有的词"}' | jq .
通关：B 在公开前搜不到；改 isPublic 后立刻能搜到；A / Admin 行为符合规则表。

设计决策

为什么规则集中在 document-access.ts？

Postgres / ES / Neo4j 语法不同，但业务规则必须同一处；改「审核员是否豁免」时只改 accessFromUser。

为什么 ES 用 filter 而不是 must？

filter 不打分、可缓存；避免「团队匹配」把相关性分数搅乱。

为什么改可见性不重跑向量？

向量与正文无关；updateByQuery / Neo4j SET 成本远低于 re-embed。
